Leveraging [parallel mode](/merge-queue/optimizations/parallel-queues) for Trunk Merge Queue is easy for Nx-enabled repos because Nx already knows the structure of your code and can automatically generate a dependency graph. Merge can use this information in parallel mode to create dynamic parallel queues enabling your pull requests to run through your Merge Queue faster.\
\
**How do we create parallel queues?**\
By understanding which Nx targets a pull request affects, we can build a real-time graph and detect intersection points and where distinct non-overlapping graphs exist. This information is essentially a list of unique target names, which can then be used in real time to understand along which targets pull requests might overlap.

**Calculating impacted targets in GitHub Actions**\
Trunk ships a [GitHub action](https://github.com/trunk-io/nx-action) that will generate the list of impacted targets for a pull request and post that information to the Trunk Merge Queue service.

```yaml
name: Upload and Test Impacted Targets
on: pull_request

jobs:
  impacted_targets:
    name: Impacted Targets
    runs-on: ubuntu-latest
    permissions:
      contents: read
      id-token: write # lets the action log in to Trunk with the run's GitHub credential
      # pull-requests: read # add if you set impact-all-filters-path in a private repository
    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: compute impacted targets
        uses: trunk-io/nx-action@v1
        with:
          auth: github-actions
```

The above sample GitHub action code will calculate the impacted targets of your pull request and post that information to the trunk merge service. That data will be used to run your trunk merge queue in parallel mode.

`auth: github-actions` logs the job in to Trunk with the run's own GitHub credential through [`trunk-io/login`](https://github.com/trunk-io/login), so there's no Trunk secret to store, and the action uploads through the v2 API. It also works on pull requests from forks once an admin [allows them](/merge-queue/reference/api-v2/github-actions#allow-uploads-from-forks). The login doesn't run on Windows runners; use a stored token there.

To use a stored token instead, leave out `auth` and `id-token: write`, and pass `trunk-token: ${{ secrets.TRUNK_API_TOKEN }}`. Set that secret to your organization API token, from the **Organization API token (v1)** section of [Settings → Developer → API Keys](https://app.trunk.io/settings/developer/api-tokens). With a token, the action uploads through the v1 [`/setImpactedTargets`](/merge-queue/reference/merge/set-impacted-targets-for-a-pull-request) endpoint, which will be deprecated soon, so an API key won't work here.
