<Warning>
  Dynamic CI is in **private beta**, and your organization has to be enabled for
  it first. Reach out on [Slack](https://slack.trunk.io). The plugin's options
  may change between releases, so pin an exact tag.
</Warning>

On Buildkite, Dynamic CI is the
[`trunk-io/dynamic-ci-buildkite-plugin`](https://github.com/trunk-io/dynamic-ci-buildkite-plugin).
You pipe your pipeline through it on the way to `buildkite-agent pipeline upload`,
and it marks the steps Trunk recommends skipping before any agent picks them up.

## Before you start

- **Set up Trunk CI for the repository.** Follow
  [Set up Trunk CI](/ci/get-started) and
  [Set up Trunk CI for Buildkite](/ci/get-started/buildkite). The pipeline's git
  remote must be on **github.com**.
- **Install the [Trunk CI](/setup/integrations/github/trunk-ci) GitHub App** on
  the repository.
- **Store your organization API token** as a Buildkite secret named
  `TRUNK_API_TOKEN`. It is under **Settings** → **Organization** → **General**
  → **API Token** in the Trunk app.
- **Give every step you might want skipped a `key:`.** A step without one always
  runs.

## Start with a dry run

Add this step to each pull request pipeline that runs your tests and checks. It
asks Trunk for a plan and discards it, so your pipeline is unchanged while Trunk
builds a history of verdicts.

```yaml
- label: ":trunk: Dynamic CI (learning, no-op)"
  timeout_in_minutes: 5
  secrets:
    - TRUNK_API_TOKEN
  # Replace .buildkite/pr-checks.yml with your pipeline file, or pipe your
  # pipeline generator's output into trunk-dynamic-ci-filter instead.
  command: trunk-dynamic-ci-filter < .buildkite/pr-checks.yml > /dev/null
  plugins:
    - trunk-io/dynamic-ci#v0.1.1:
        token-env: TRUNK_API_TOKEN
```

Use the same `if:` and `agents:` as your other pull request steps.

## Add the plugin to your upload step

When you are ready to skip steps, pipe your pipeline through the filter on its
way to upload:

```yaml
steps:
  - label: ":pipeline: upload"
    secrets:
      - TRUNK_API_TOKEN
    command: |
      cat .buildkite/pipeline.yml \
        | trunk-dynamic-ci-filter \
        | buildkite-agent pipeline upload
    plugins:
      - trunk-io/dynamic-ci#v0.1.1:
          token-env: TRUNK_API_TOKEN
```

For a generated pipeline, pipe your generator's output in place of `cat`.

- **Pin an exact tag** from
  [Releases](https://github.com/trunk-io/dynamic-ci-buildkite-plugin/releases),
  v0.1.1 or later. Not `#main` or a major alias.
- **Do not pass `--no-interpolation`** to `buildkite-agent pipeline upload`.
- **`trigger:` steps are never skipped.** Matrix and `parallelism:` legs share
  one key, so they run or skip together.

Then set the repository to **Enforced**: in the Trunk app, navigate to
**Dynamic CI** → **[your repository]** and change the **Dynamic CI mode**. Until
then, nothing is skipped. To stop using Dynamic CI, remove the plugin, or set the
repository back to **Learning**.

## Steps that must never be skipped

Trunk cannot tell which Buildkite steps are required to merge, so mark them
before you enforce. Either list them in `exclude-keys`:

```yaml
plugins:
  - trunk-io/dynamic-ci#v0.1.1:
      token-env: TRUNK_API_TOKEN
      exclude-keys: deploy-master,publish-release
```

Or, in the Trunk app, navigate to **Dynamic CI** → **[your repository]** →
**Configuration**, open the pipeline, and set the step to **Always run**.

To try Dynamic CI on a single step first, use `only-keys: <key>` instead.

## Limitations

- **Merge-queue builds** (`trunk-merge/` or `gh-readonly-queue/` branches) skip
  nothing unless you have configured a paths filter.
- **Builds without a pull request**, such as pushes to your default branch, can
  be skipped. Leave the plugin off those uploads if you don't want that.
- **Force overrides** from the
  [browser extension](/dynamic-ci#force-a-job-to-run) are not available for
  Buildkite yet.

## Troubleshooting

Set `debug: true` to print the step keys the plugin asked about, the request it
sent and the plan it got back.

- **Nothing is skipped.** Check that the repository is **Enforced**, that the
  steps have a `key:`, and that Trunk has a couple of weeks of builds for them.
- **The plan request returns 404.** The pipeline's remote does not match a
  repository in your Trunk organization with CI data.
- **`baseSha` is null on a pull request build.** Your checkout does not have the
  target branch. Fetch it before the upload step.
- **A step was skipped that shouldn't have been.** Set it to **Always run** or add
  it to `exclude-keys`, and tell us on [Slack](https://slack.trunk.io).

If Trunk is unavailable, the plugin uploads your pipeline unchanged.

## Step mode

If your pipeline lives in Buildkite's settings editor and has no upload step,
put the plugin on the step itself with `mode: step`. The step must have a `key:`.
It saves less, because the agent has already started, and a skipped step
reports as passed rather than skipped.

## Options

| Option           | Default       | Description                                                                         |
| ---------------- | ------------- | ----------------------------------------------------------------------------------- |
| `mode`           | `filter`      | `filter` for your upload pipe, `step` to decide about the step the plugin is on.    |
| `token-env`      | `TRUNK_TOKEN` | The environment variable holding your Trunk API token.                              |
| `only-keys`      | unset         | Comma-separated step keys to consider. Every other step runs.                       |
| `exclude-keys`   | unset         | Comma-separated step keys to never skip. Wins over `only-keys`.                     |
| `debug`          | `false`       | Print the requested keys, the request and the plan to the build log.                |
| `ignore-signals` | unset         | Comma-separated signal identifiers to leave out of the recommendation. Ask us for the list. |
