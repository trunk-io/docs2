The [`trunk-io/dynamic-ci`](https://github.com/trunk-io/dynamic-ci) action connects a GitHub Actions workflow to Dynamic CI. It asks Trunk which jobs the current change needs and writes one output per job. Your jobs read those outputs in their `if:` conditions to decide whether to run.

## Usage

The action sets one output per job in the workflow, named by the job key. Outputs are set at runtime, so re-export each one from the filter job's `outputs:` under the same key:

```yaml
jobs:
  dynamic-ci:
    runs-on: ubuntu-latest
    outputs:
      # 'false': Trunk recommends skipping the job.
      # Any other value: Trunk recommends running the job.
      # Empty: no verdict (Trunk unreachable, missing token, or no history
      # yet). The job should run.
      unit-tests: ${{ steps.dynamic-ci.outputs.unit-tests }}
    steps:
      - uses: actions/checkout@v7
        with:
          clean: false
      - uses: trunk-io/dynamic-ci@v1
        with:
           # A Trunk API key (starts with trunk_v2_). No permissions needed.
           # Store it as a repository or organization
           # secret, such as TRUNK_API_TOKEN
           # Required.
           token: ${{ secrets.TRUNK_API_TOKEN }}

           # Token used to read the pull request's changed files when the checkout
           # does not contain both the base and head commits
           # Default: ${{ github.token }}
           github-token: ''

           # Post the recommendation for each job to the run's annotations and job
           # summary, so verdicts show on the run's summary page
           # Default: false
           enable-annotation: ''

           # A JSON object of job key to the rows a planner job built for that
           # job's matrix. Only for matrix jobs decided by variation.
           # Default: unset
           matrices: ''
```

## Matrix outputs

A matrix job [decided by variation](/ci/dynamic-ci/configuration/matrices) can
also get one of these outputs (v0.1.8 or later), depending on [how its matrix is
written](/ci/dynamic-ci/getting-started/github-actions#read-the-variations-to-run).
Each is set only when some variations are skipped and others run.

| Output | Value | Read it at |
| --- | --- | --- |
| `<job>-exclude` | A JSON list of the skipped combinations, after your own exclusions | `strategy.matrix.exclude`, for an Axis matrix |
| `<job>-matrix` | A JSON object, `{"include": [...]}`, of the rows that run | `strategy.matrix`, for a Fixed-include matrix |
| `<job>-include` | A JSON list of the rows that run | `strategy.matrix.include`, for a Dynamic-include matrix |

When every variation is skipped, `<job>` is `'false'` and the job is skipped
whole.

## Fail-open behavior

The action is built so a problem never causes a job to be skipped by mistake. It retries requests to Trunk, and when it still cannot get a verdict, the output is empty and the job will run.

## Checkout

The action compares the pull request's base and head commits to find the changed files.`actions/checkout` with `clean: false` is enough. When the checkout does not contain both commits, the action falls back to `github-token` to read the changed files.

## Versioning

Pin to the major version tag, `trunk-io/dynamic-ci@v1`, to receive compatible updates automatically.

## GitHub token permissions

Grant the workflow `pull-requests: read` so `github-token` can read the pull request's changed files:

```yaml
permissions:
  contents: read
  pull-requests: read
```
