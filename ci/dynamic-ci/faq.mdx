## Reliability

<AccordionGroup>
  <Accordion title="What happens if Trunk is slow or down?">
    Every job runs. The action is built to retry for resiliency, but if Trunk is
    down, the action will fail open and all your jobs will run.
  </Accordion>

  <Accordion title="What does the Buildkite plugin do if Trunk is unavailable?">
    It uploads your pipeline unchanged, so every step runs.
  </Accordion>

  <Accordion title="What happens to a job Trunk has never seen?">
    It runs. A job needs a couple of days of history before Trunk will
    recommend skipping it.
  </Accordion>

  <Accordion title="Can Dynamic CI skip a job in my merge queue?">
    Only when a paths filter you configured excludes it. See
    [Merge queues](/ci/dynamic-ci/merge-queue).
  </Accordion>

  <Accordion title="Can I make sure a skipped job runs before a pull request enters the queue?">
    Yes. Set the job to [Run Before Queue](/ci/dynamic-ci/run-before-queue).
    Trunk starts it on the head commit before the pull request enters the
    queue, unless it already ran there.
  </Accordion>

  <Accordion title="Why is my pull request held with a Run Before Queue line?">
    Trunk is starting its Run Before Queue jobs on the head commit. If the
    line says **Run Before Queue failed to start**, force the jobs and rerun,
    or push. See [Failed to start](/ci/dynamic-ci/run-before-queue#failed-to-start).
  </Accordion>
</AccordionGroup>

## Forks

<AccordionGroup>
  <Accordion title="What happens on pull requests from forks?">
    A pull request from a fork has no access to your repository's secrets, so
    the filter job has no token and every job runs.
  </Accordion>

  <Accordion title="Does Run Before Queue build pull requests from forks on Buildkite?">
    No. Trunk creates no build for a fork pull request, because it would run
    fork code with the pipeline's secrets. Run Before Queue fails to start
    until someone with access to the pipeline runs the steps on the head
    commit.
  </Accordion>
</AccordionGroup>
