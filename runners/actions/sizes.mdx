---
title: "Machine sizes"
description: "Choose CPUs with size and memory per CPU with memory."
---

Set `size` to choose how many CPUs a job gets, and `memory` to choose how much
memory it gets per CPU.

```yaml
runs-on: trunk=${{ github.run_id }}-${{ github.run_attempt }}..size=large..memory=high
```

## Sizes

| Size     | CPUs | `memory=low` | `memory=standard` | `memory=high` |
| -------- | ---- | ------------ | ----------------- | ------------- |
| `xsmall` | 1    | 1 GiB        | 2 GiB             | 4 GiB         |
| `small`  | 2    | 2 GiB        | 4 GiB             | 8 GiB         |
| `medium` | 4    | 4 GiB        | 8 GiB             | 16 GiB        |
| `large`  | 8    | 8 GiB        | 16 GiB            | 32 GiB        |
| `xlarge` | 16   | 16 GiB       | 32 GiB            | 64 GiB        |

`memory` is 1, 2, or 4 GiB per CPU, and defaults to `standard` when you set a
`size`.

## The default machine

With no `size`, a job gets 2 CPUs and 8 GiB, the same machine as GitHub's
`ubuntu-latest` runner for private repositories. Jobs you move over keep the
machine they had.

```yaml
runs-on: trunk=${{ github.run_id }}-${{ github.run_attempt }}
```

<Warning>
  `size=small` on its own is 2 CPUs and 4 GiB, half the memory of the default
  machine. Use `size=small..memory=high` if you want to name the size and keep 8
  GiB.
</Warning>

## Picking a size

Start with the size closest to what the job ran on before. Use `memory=high`
for jobs that run out of memory, such as large builds, and `memory=low` for
jobs that need CPUs but not much memory.

An unknown value, such as `size=huge`, gets no runner: the job stays queued
with no error. See the [label rules](/runners/reference/runs-on-grammar#rules).
