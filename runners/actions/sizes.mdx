The `size` option sets the CPU count of the runner. `size` is optional. The
default size is `small`. A job that leaves out `size` runs on the
[default machine](#the-default-machine).

## Sizes

The memory columns are the values of the `memory` option.

| Size     | CPUs | `low`  | `standard` (default with a `size`) | `high`                      |
| -------- | ---- | ------ | ---------------------------------- | --------------------------- |
| `xsmall` | 1    | 1 GiB  | 2 GiB                              | 4 GiB                       |
| `small`  | 2    | 2 GiB  | 4 GiB                              | 8 GiB (the default machine) |
| `medium` | 4    | 4 GiB  | 8 GiB                              | 16 GiB                      |
| `large`  | 8    | 8 GiB  | 16 GiB                             | 32 GiB                      |
| `xlarge` | 16   | 16 GiB | 32 GiB                             | 64 GiB                      |

With `size` set and no `memory`, the runner uses `memory=standard`. With no
`size`, the runner is the [default machine](#the-default-machine): `small` with
`memory=high`, 2 CPUs and 8 GiB.

```yaml
runs-on: trunk=${{ github.run_id }}-${{ github.run_attempt }}..size=large
```

## The default machine

If you leave out `size`, the job runs on a `small` runner with high memory: 2 CPUs
and 8 GiB. This is the same machine as the GitHub Actions `ubuntu-latest` runner in a
private repository, so a job that you move to Trunk Runners keeps the machine it had.

```yaml
runs-on: trunk=${{ github.run_id }}-${{ github.run_attempt }}
```

<Note>
  An unknown size, such as `size=huge`, gets no runner, and the job stays queued
  with no message. See the [label
  rules](/runners/reference/runs-on-grammar#rules).
</Note>

## Memory

The `memory` option sets the memory per CPU. The size still sets the CPU count.

| `memory`   | Memory per CPU |
| ---------- | -------------- |
| `low`      | 1 GiB          |
| `standard` | 2 GiB          |
| `high`     | 4 GiB          |

See [Sizes](#sizes) for the CPUs and memory of each size with each `memory`
value.

```yaml
runs-on: trunk=${{ github.run_id }}-${{ github.run_attempt }}..size=large..memory=high
```

<Warning>
  `size=small` and no size are different machines. `size=small` gives 2 CPUs and
  4 GiB. No size gives 2 CPUs and 8 GiB, because the default machine uses high
  memory. To get the default machine and also name its size, use
  `size=small..memory=high`.
</Warning>

<Tip>
  Start with a size that matches your job. Add `memory=high` only for a job that
  runs out of memory, such as a large build or a test suite that holds a lot of
  data. Use `memory=low` for a job that needs CPUs but little memory.
</Tip>
