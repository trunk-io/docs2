Trunk Runners run your GitHub Actions jobs on Trunk's bare-metal fleet. Your
workflows stay on GitHub. You change one line, the `runs-on` label, and Trunk
starts a fresh VM for the job and removes it when the job ends.

## Fast

- **Faster hardware.** Jobs run on bare metal, about 40% faster than comparable
  AWS machines.
- **Templates.** Bake your setup steps into a [template](/runners/actions/templates-and-regions)
  so a job starts ready, instead of installing the same tools on every run.
- **In-cluster cache.** `actions/cache`, Bazel, sccache, and Nix use a shared
  cache in the same cluster as your jobs, with no workflow changes.
  `actions/cache` runs at about 275 MiB/s, against about 110 MiB/s on GitHub.
  See [Caching](/runners/cache/index).

## Reliable

- **Managed for you.** Trunk runs the fleet, images, and caches. No self-hosted
  runners to maintain.
- **Priority branches.** Your default, release, and merge queue branches start
  first when CI is busy. See
  [Quota and runner priority](/runners/settings/limits-and-priority).
- **Nothing dropped.** At your CPU quota, new jobs wait and start as CPUs free
  up.

## Affordable

- **Usage-based.** You pay for the CPUs and memory a job's machine has while
  the job runs. The default machine costs $0.006 per minute. See
  [Pricing](/runners/pricing).
- **Right-sized.** Mix CPU and memory per job, so a lint job does not pay for a
  build machine. See [Machine sizes](/runners/actions/sizes).
- **Run less CI.** Pair with [Dynamic CI](/ci/dynamic-ci/index) to skip jobs a
  change cannot affect.
