## How it works

You keep your workflows on GitHub. You change one thing: the `runs-on` label of a
job. That label tells Trunk to run the job. Trunk starts a VM, runs the job, and
removes the VM when the job ends.

<Card title="Get started" icon="arrow-right" href="/runners/getting-started">
  Turn on Trunk Runners for your organization and run your first job.
</Card>

## What you can configure

- **The runner** — the `runs-on` label sets the size you need and the template to
  start on. See [The runs-on label](/runners/actions/runs-on).
- **Caching** — choose which build tools use the shared cache, per repository or
  for the whole organization, and see what is cached. See
  [Caching](/runners/cache/index).
- **Organization defaults** — set a default template. See
  [Organization defaults](/runners/settings/ci-defaults).
- **Limits and priority** — set a CPU limit for CI and mark priority branches.
  See [Limits and priority](/runners/settings/limits-and-priority).
