A webhook tells you about each test the moment its status changes. A weekly digest shows the week as a whole: which tests got worse, which recovered, and which team owns each one. That's what a triage meeting needs. Trunk's [API](/api) has everything the digest needs, so a short script on a schedule can build it.

## 1. Find the tests whose status changed

Every test has a `status` (`healthy`, `flaky` or `broken`) and a `statusSince`, the time that status began. A test changed this week if its `statusSince` is within the last seven days. Don't look for those tests by listing every test. An organization can have hundreds of thousands of healthy tests. Make two short lists instead, paging through each with `nextCursor`:

- **Turned flaky or broken.** Call [`GET /v2/tests`](/api/tests/list-and-search-tests) with `status=flaky,broken`, `include=metrics` and `period=7d`. The metrics give each test's failure rate for the week.
- **Turned healthy.** A test recovers when a monitor stops flagging it, and the monitor records that as an event. Call [`GET /v2/detection-events`](/api/detectionevents/list-detection-events) with `isClassificationEvent=true`, `monitorStatus=inactive` and `detectedAfter` set to the start of the week. For each test in those events that isn't in the first list, call [`GET /v2/tests/{testId}`](/api/tests/get-a-test) with `include=metrics&period=7d`.

From both lists, keep the tests whose `statusSince` is within the week. Add `testCollectionId` to the list calls to send a digest for one collection.

<Note>
Use `statusSince` rather than `newlyFlaky=true`. `newlyFlaky` returns only tests that became flaky for the first time. It leaves out a test that was fixed and then turned flaky again, and a test that turned broken. Detection events don't include a test someone [flagged as flaky](../management/managing-detected-flaky-tests) by hand. So if someone clears that flag and the test turns healthy, the test isn't in the digest.
</Note>

## 2. Compare with the start of the week

A test can change status more than once in a week. For example, it can turn flaky on Monday and recover on Thursday. For each test from step 1, call [`GET /v2/tests/{testId}/status-history`](/api/tests/list-a-tests-status-transitions) with `startedAfter` set to the start of the week. Transitions are listed newest first, so the last one's `fromStatus` was the test's status when the week began.

- If that status is the same as the test's current `status`, the test changed and then changed back. Leave it out.
- Otherwise, report the test as `fromStatus` → `status`, such as `healthy → flaky` or `broken → healthy`.

Each transition's `activeMonitors` lists the monitors that flagged the test, if you want to show why it changed.

## 3. Group by owner and post to Slack

Each test has `codeowners`, such as `@acme/payments`. Group the tests by owner. A test with more than one owner goes under each of them, and a test with none goes under **Unowned**. Then post the groups to a Slack [incoming webhook](https://api.slack.com/messaging/webhooks). Each test's `url` links to its page in Trunk.

This script does all three steps. It needs Node.js 18 or later and an [API key](/api/authentication#api-keys). Reading tests needs no permissions, so leave them all off.

```javascript flaky-digest.mjs expandable
const API = "https://api.trunk.io/v2";
const headers = { Authorization: `Bearer ${process.env.TRUNK_API_KEY}` };
const weekStart = new Date(Date.now() - 7 * 24 * 60 * 60 * 1000);
const SEVERITY = { healthy: 0, flaky: 1, broken: 2 };

async function get(path, params) {
  const url = new URL(API + path);
  for (const [key, value] of Object.entries(params)) url.searchParams.set(key, value);
  const res = await fetch(url, { headers });
  if (res.status === 404) return null;
  if (!res.ok) throw new Error(`${res.status} ${path}: ${await res.text()}`);
  return res.json();
}

async function listAll(path, params) {
  const rows = [];
  let cursor;
  do {
    const page = await get(path, { ...params, limit: 100, ...(cursor && { cursor }) });
    rows.push(...page.data);
    cursor = page.nextCursor;
  } while (cursor);
  return rows;
}

async function tenAtATime(items, fn) {
  const results = [];
  for (let i = 0; i < items.length; i += 10) {
    results.push(...(await Promise.all(items.slice(i, i + 10).map(fn))));
  }
  return results;
}

const unhealthy = await listAll("/tests", { status: "flaky,broken", include: "metrics", period: "7d" });
const unhealthyIds = new Set(unhealthy.map((t) => t.id));
const recoveries = await listAll("/detection-events", {
  isClassificationEvent: true,
  monitorStatus: "inactive",
  detectedAfter: weekStart.toISOString(),
});
const recoveredIds = [...new Set(recoveries.map((e) => e.testId))].filter((id) => !unhealthyIds.has(id));
const recovered = await tenAtATime(recoveredIds, (id) => get(`/tests/${id}`, { include: "metrics", period: "7d" }));

const candidates = [...unhealthy, ...recovered].filter(
  (t) => t?.statusSince && new Date(t.statusSince) >= weekStart,
);
const changes = (
  await tenAtATime(candidates, async (test) => {
    const history = await get(`/tests/${test.id}/status-history`, {
      startedAfter: weekStart.toISOString(),
      limit: 100,
    });
    const from = history?.data.at(-1)?.fromStatus;
    return from && from !== test.status ? { ...test, from } : null;
  })
).filter(Boolean);

const byOwner = new Map();
for (const test of changes) {
  for (const owner of test.codeowners.length ? test.codeowners : ["Unowned"]) {
    byOwner.set(owner, [...(byOwner.get(owner) ?? []), test]);
  }
}

const escape = (text) => text.replace(/&/g, "&amp;").replace(/</g, "&lt;").replace(/>/g, "&gt;");
const line = (t) => {
  const rate = t.metrics ? `, ${Math.round(t.metrics.failureRate * 100)}% of ${t.metrics.runCount} runs failed` : "";
  return `• <${t.url}|${escape(t.name.slice(0, 80))}>: ${t.from} → ${t.status}${rate}`;
};

const blocks = [{ type: "header", text: { type: "plain_text", text: "Flaky tests this week" } }];
if (byOwner.size === 0) {
  blocks.push({ type: "section", text: { type: "mrkdwn", text: "No test changed status this week." } });
}
for (const [owner, tests] of [...byOwner].sort(([a], [b]) => a.localeCompare(b)).slice(0, 49)) {
  tests.sort((a, b) => SEVERITY[b.status] - SEVERITY[a.status]);
  const more = tests.length > 8 ? `\n…and ${tests.length - 8} more` : "";
  blocks.push({
    type: "section",
    text: { type: "mrkdwn", text: `*${escape(owner)}*\n${tests.slice(0, 8).map(line).join("\n")}${more}` },
  });
}

const res = await fetch(process.env.SLACK_WEBHOOK_URL, {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ text: "Flaky tests this week", blocks }),
});
if (!res.ok) throw new Error(`Slack: ${res.status} ${await res.text()}`);
```

The script makes up to 10 requests at a time and lists up to 8 tests for each owner, worst first, and up to 49 owners, which stays within Slack's limits for one message. To send each team its own digest, keep only that team's group from `byOwner` and post it to the team's webhook URL.

## 4. Run it every week

Run the script from any scheduler, such as cron or a scheduled CI job. This GitHub Actions workflow posts every Monday at 14:00 UTC. Store the API key and the Slack webhook URL as repository secrets:

```yaml .github/workflows/flaky-digest.yml expandable
name: Weekly flaky test digest
on:
  schedule:
    - cron: "0 14 * * 1"
  workflow_dispatch:

jobs:
  digest:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
      - run: node flaky-digest.mjs
        env:
          TRUNK_API_KEY: ${{ secrets.TRUNK_API_KEY }}
          SLACK_WEBHOOK_URL: ${{ secrets.SLACK_WEBHOOK_URL }}
```

The number of requests depends on how many tests are unhealthy or changed status this week, not on how many tests you have. On an organization with over 275,000 tests and about 2,300 unhealthy ones, the digest made about 1,300 requests and took under 90 seconds. Requests share your organization's [rate limit](/api/rate-limits), so run the digest outside working hours.
