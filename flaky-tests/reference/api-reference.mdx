The Trunk Flaky Tests API is an HTTP REST API, returns JSON from all requests, and uses standard HTTP response codes.

**Endpoints come in two scopes, and they are not interchangeable.** Which one you want depends on how your tests are organized — see [migrating to test collections](/flaky-tests/get-started/migrate-to-test-collections) if you are moving between them.

## Test collection endpoints

Scoped to [test collections](/flaky-tests/test-collections), on `/v2`. Use these if your tests are organized into collections.

Authenticate with an [API key](/merge-queue/reference/api-v2/authentication), sent as `Authorization: Bearer <key>`. The organization API token works only with the v1 API. Switch on an error's `code`, not its `message`. Authentication failures and rate limiting come from Trunk's edge and may lack the error envelope, so branch on the status code for those.

## Repository endpoints

Scoped to repositories, on `/v1`. Use these if your tests are still organized by repository.

Authenticate these with your organization API token in the `x-api-token` header. See [Authentication](../../setup-and-administration/apis/#authentication). v2 API keys don't work with v1.

<Warning>
The v1 repository endpoints will be deprecated soon. Use the [test collection endpoints](#test-collection-endpoints) instead, with an [API key](/merge-queue/reference/api-v2/authentication). To move your tests into collections first, see [Migrate to test collections](/flaky-tests/get-started/migrate-to-test-collections). The Trunk Analytics CLI and `trunk-io/analytics-uploader` still need the organization API token.
</Warning>

## Choosing between them

The two scopes are separate APIs rather than two versions of one, so there is not a collection equivalent of every repository endpoint:

| If you want to | Repository endpoint | Collection endpoint |
|---|---|---|
| Read one test | Get the details of a test case | Get a test |
| Find unhealthy tests | Get a list of unhealthy tests | List and search tests, filtered by status |
| Find quarantined tests | Get a list of quarantined tests | List and search tests, filtered by quarantine state |
| Find recent failures | Get a list of distinct tests that failed | List a test's runs |
| Link a ticket to a test | Link a ticket to a test case | Link a ticket to a test |
| File a new ticket for a test | *Not applicable* | Create a ticket for a test |
| List or create collections | *Not applicable* | List / Create a test collection |

<Note>
A test's ID is not the same value in both scopes, so an ID read from a repository endpoint cannot be passed to a collection endpoint or vice versa. The repository's `repository.id` is the only identifier the two share.
</Note>
