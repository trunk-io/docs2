**Flaky Tests webhook delivery now retries automatically when the delivery provider rate-limits a request.**

Previously, a 429 response from Svix would cause a webhook event to fail without retrying. Now the service retries up to four times with exponential backoff and full jitter, starting at a 500ms delay. Most transient rate-limit windows resolve within a few seconds, so webhook consumers should see fewer missed events during traffic spikes without any change to their configuration.

This improvement applies to all Flaky Tests webhook event types, including test status changes, AI investigation results, and quarantine updates.

[Read the webhook docs](/flaky-tests/webhooks) to learn more.
