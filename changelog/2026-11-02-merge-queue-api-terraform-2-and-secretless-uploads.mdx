**Manage merge queues with scoped API keys, and upload impacted targets without storing a Trunk secret.**

### New features

- **Merge Queue API is public.** Manage queues and the pull requests in them, read the order the queue will test them in, and inspect each verification run. Authenticate with an API key that holds only the permissions your automation needs. See the [API reference](/api) and [Authentication](/api/authentication).
- **Terraform provider 2.0.** The `trunk-io/trunk` provider now accepts API keys and manages two more settings: `test_branch_construction_mode` and `batching_rules`. Most configurations upgrade unchanged. See [Migrate to Terraform provider 2.0](/merge-queue/administration/terraform-migrate-to-2).
- **Bazel and Nx uploads without a Trunk secret.** Set `auth: github-actions` in the Bazel or Nx action to upload impacted targets with the run's own GitHub credential. See [Bazel](/merge-queue/optimizations/parallel-queues/bazel) and [Nx](/merge-queue/optimizations/parallel-queues/nx).
- **Impacted targets from fork PRs.** On public repositories, admins can turn on this setting so fork pull requests can upload impacted targets. See [Allow uploads from forks](/merge-queue/optimizations/parallel-queues/github-actions#allow-uploads-from-forks).

### Updates

- **Organization API token has moved.** Find it under **Settings** → **Developer** → **API Keys**, in the **Organization API token (v1)** section. Admins can also create a token there if your organization doesn't have one. See [Legacy API authentication](/api/authentication/legacy).
- **Terraform `required_statuses` behaves differently in 2.0.** Leaving it out no longer removes a queue's override. Set `required_statuses = []` to clear it. See [What changes](/merge-queue/administration/terraform-migrate-to-2#what-changes).

### Bug fixes

- **Terraform no longer drops queues from state on a bad token.** In provider 2.0, a wrong or revoked token, or an unknown repository, fails the refresh instead.
- **Terraform refreshes no longer write to queues on hosts other than `github.com`** when you use the organization API token. Provider 2.0 shows a warning instead. Use an API key to update those queues.
